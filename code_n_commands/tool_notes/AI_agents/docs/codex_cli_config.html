目标是在 VS Code 中使用 Codex 扩展，并让 Codex 通过自定义 OpenAI 兼容 API 端点工作：

https://www.souimagery.fun/v1

使用模型：

gpt-5.5

核心配置思路：

  • Codex CLI 使用 C:\Users\Kalil\.codex\config.toml 配置模型、API 端点和请求协议。
  • VS Code Codex 扩展使用 C:\Users\Kalil\AppData\Roaming\Code\User\settings.json 中的 chatgpt.* 配置。
  • API key 使用 auth.json 或 .env 保存，不要写入公开文档。
  • 必须保留 wire_api = "chat"，让请求走 Chat Completions 兼容路径。

1. 准备环境

确认 VS Code 已安装 Codex 扩展：

openai.chatgpt

1.1 Node.js 配置方法

Codex CLI 通过 npm 安装，所以需要先让 Windows 终端能正常调用 node 和 npm。

先检查本机是否已经安装：

node -v
npm -v
where node
where npm

如果 node -v 和 npm -v 都能输出版本号，说明 Node.js 和 npm 已经可用。

如果提示找不到命令，改用命令行安装 Node.js LTS。npm 会随 Node.js 一起安装，不需要单独下载 npm。

1.1.1 使用 winget 安装 Node.js LTS（推荐）

先确认 Windows 包管理器 winget 可用：

winget --version

如果能输出版本号，执行：

winget source update
winget install --id OpenJS.NodeJS.LTS -e --source winget

如果提示权限不足，以管理员身份打开 PowerShell 后重新执行安装命令。

如果本机已经安装过 Node.js LTS，需要更新版本，可以执行：

winget upgrade --id OpenJS.NodeJS.LTS -e --source winget

安装或更新完成后，关闭当前 PowerShell 或 CMD，再重新打开一个终端。

1.1.2 使用 PowerShell 下载官方 LTS MSI（备用）

如果没有 winget，可以用 PowerShell 从 Node.js 官方发布索引自动选择最新 LTS，并下载对应 Windows MSI 安装包：

$ErrorActionPreference = "Stop"
$ProgressPreference = "SilentlyContinue"

$arch = if ($env:PROCESSOR_ARCHITECTURE -eq "ARM64") {
  "arm64"
} elseif ([Environment]::Is64BitOperatingSystem) {
  "x64"
} else {
  "x86"
}

$index = Invoke-RestMethod "https://nodejs.org/dist/index.json"
$lts = $index | Where-Object { $_.lts -ne $false } | Select-Object -First 1
$msiName = "node-$($lts.version)-$arch.msi"
$msiUrl = "https://nodejs.org/dist/$($lts.version)/$msiName"
$msiPath = Join-Path $env:TEMP $msiName

Write-Host "Downloading $msiUrl"
Invoke-WebRequest -Uri $msiUrl -OutFile $msiPath

Write-Host "Installing $msiPath"
Start-Process msiexec.exe -Wait -ArgumentList "/i `"$msiPath`" /passive /norestart"

安装完成后，关闭当前 PowerShell 或 CMD，再重新打开一个终端。

重新验证：

node -v
npm -v
where node
where npm

正常情况下，where node 会包含类似路径：

C:\Program Files\nodejs\node.exe

如果安装后仍然找不到 node，检查 Windows 环境变量：

  1. 打开 Windows 搜索，输入 环境变量。
  2. 打开 编辑系统环境变量。
  3. 点击 环境变量。
  4. 在 系统变量 或 用户变量 的 Path 中确认存在：
C:\Program Files\nodejs\
  1. 保存后重新打开终端，再执行 node -v 和 npm -v。

1.2 npm 配置方法

npm 是 Node.js 自带的包管理器。安装 Codex CLI 前，先确认 npm 的 registry、全局安装目录、缓存目录和 PATH。

查看 npm 当前配置：

npm config list
npm config get registry
npm config get prefix
npm root -g
npm config get cache

常用字段含义：

  • registry：npm 下载包使用的软件源。
  • prefix：npm 全局安装命令行工具的位置。
  • npm root -g：npm 全局包实际安装目录。
  • cache：npm 缓存目录。

1.2.1 配置 npm registry

如果网络访问 npm 官方源正常，建议使用官方 registry：

npm config set registry https://registry.npmjs.org/
npm config get registry

如果访问官方 registry 很慢，可以临时使用国内镜像：

npm config set registry https://registry.npmmirror.com
npm config get registry

切回官方 registry：

npm config set registry https://registry.npmjs.org/

测试 registry 是否可用：

npm ping
npm view @openai/codex version

1.2.2 配置 npm 全局安装目录

查看当前全局安装目录：

npm config get prefix
npm root -g

Windows 上常见的用户级全局目录是：

C:\Users\Kalil\AppData\Roaming\npm

如果 npm config get prefix 指向 Anaconda 路径，而你不想继续让 npm 使用 Anaconda，可以改成用户级目录：

npm config set prefix "$env:APPDATA\npm"
npm config get prefix

然后确认该目录在用户 Path 中：

$env:Path -split ';' | Where-Object { $_ -match 'npm|nodejs|Anaconda' }

如果 C:\Users\Kalil\AppData\Roaming\npm 不在 PATH 中，按下面方式添加：

  1. 打开 Windows 搜索，输入 环境变量。
  2. 打开 编辑系统环境变量。
  3. 点击 环境变量。
  4. 选中用户变量里的 Path，点击 编辑。
  5. 添加：
C:\Users\Kalil\AppData\Roaming\npm
  1. 保存后完全关闭并重新打开终端。

重新验证：

npm config get prefix
where npm

1.2.3 配置 npm 缓存

查看缓存目录：

npm config get cache

检查缓存是否健康：

npm cache verify

如果安装包时反复出现缓存损坏类错误，可以清理缓存：

npm cache clean --force
npm cache verify

1.2.4 配置 npm 代理（可选）

如果当前网络必须走代理才能访问 npm registry，可以设置代理。下面端口只是示例，按自己的代理软件填写：

npm config set proxy http://127.0.0.1:7890
npm config set https-proxy http://127.0.0.1:7890
npm config get proxy
npm config get https-proxy

如果不再需要代理，删除代理配置：

npm config delete proxy
npm config delete https-proxy

不建议随意关闭 SSL 校验。只有明确知道证书链问题并能承担风险时，才考虑相关配置。

1.2.5 更新 npm（可选）

如果 npm 版本太旧，可以更新 npm：

npm install -g npm
npm -v

更新后重新打开终端，再执行：

where npm
npm -v

1.3 安装 Codex CLI

确认 Node.js 和 npm 可用后，安装 Codex CLI：

npm install -g @openai/codex
codex --version

如果之前装过旧版本，可以重新安装：

npm uninstall -g @openai/codex
npm install -g @openai/codex
codex --version

检查 codex 命令实际来自哪里：

where codex

如果输出路径中同时出现 Anaconda 和 VS Code 扩展目录，通常优先使用 PATH 中排在前面的那个。按当前要求，Anaconda 相关历史配置可以忽略；只要 codex --version 能正常输出版本，并且 VS Code 扩展可以正常调用 Codex，即可继续后续步骤。

2. 配置 Codex CLI

编辑文件：

C:\Users\Kalil\.codex\config.toml

建议内容如下：

model           = "gpt-5.5"
model_provider  = "openai"
openai_base_url = "https://www.souimagery.fun/v1"
wire_api        = "chat"
model_reasoning_effort = "medium"

[windows]
sandbox = "elevated"

字段含义：

  • model：指定使用的模型，这里是 gpt-5.5。
  • model_provider：仍然写 openai，表示使用 OpenAI 兼容 provider。
  • openai_base_url：把 CLI 请求发到自定义端点，而不是官方 api.openai.com。
  • wire_api：设置为 chat，确保走 /v1/chat/completions 兼容接口。
  • model_reasoning_effort：推理强度。记录中出现过 high 和 medium，最终修复方案使用 medium；如果本机已改成其他可用值，也可以保留。
  • [windows].sandbox：Windows 下的沙箱配置。

如果已有项目信任配置，例如：

[projects.'某个项目路径']
trust_level = "trusted"

可以继续保留，不需要删除。

3. 配置 API Key

Codex CLI 的 key 可以保存在：

C:\Users\Kalil\.codex\auth.json

示例结构：

{
  "auth_mode": "apikey",
  "OPENAI_API_KEY": "sk-你的真实key"
}

如果使用 .env，则编辑：

C:\Users\Kalil\.codex\.env

写入：

OPENAI_API_KEY=sk-你的真实key

注意：

  • 文档中不要保存真实完整 key。
  • 如果已经有正确的 auth.json，通常无需再改。
  • 401 Unauthorized 通常表示 key 不完整、填错、过期，或请求被发到了错误端点。

4. 配置 VS Code Codex 扩展

VS Code 扩展和 Codex CLI 不是完全同一个配置入口。最终记录确认：

  • config.toml 主要控制 CLI。
  • VS Code 扩展 openai.chatgpt 需要读取 settings.json 中的 chatgpt.* 设置。
  • codex.environmentVariables 对该扩展无效。

打开 VS Code 设置 JSON：

  1. 在 VS Code 中按 Ctrl + ,
  2. 点击右上角 {} 图标，打开设置 JSON
  3. 文件位置通常是：
C:\Users\Kalil\AppData\Roaming\Code\User\settings.json

如果文件中存在以下无效配置，删除：

"codex.environmentVariables": [
  { "name": "OPENAI_BASE_URL", "value": "..." },
  { "name": "OPENAI_API_KEY", "value": "..." }
],

添加或确认以下有效配置：

"chatgpt.apiBase": "https://www.souimagery.fun/v1",
"chatgpt.config": {
  "preferred_auth_method": "apikey",
  "model": "gpt-5.5",
  "wire_api": "chat",
  "model_reasoning_effort": "medium",
  "disable_response_storage": true
},

关键点：

  • chatgpt.apiBase 必须带 /v1。
  • preferred_auth_method 使用 apikey。
  • wire_api 使用 chat，避免请求走默认的 Responses API。
  • 不要再使用 codex.environmentVariables 作为 VS Code 扩展配置。

5. 保存并完全重启 VS Code

保存 settings.json 后，必须完全重启 VS Code：

  1. Ctrl + S 保存。
  2. 关闭所有 VS Code 窗口。
  3. 检查任务栏或托盘中是否仍有残留 VS Code 进程。
  4. 重新打开 VS Code。

这一步很重要，因为扩展配置和环境变量通常需要重启后才会重新读取。

6. 验证配置

验证 CLI：

codex --version

验证 VS Code 扩展：

  1. 打开 Codex 面板，或使用命令面板运行 Codex: Open Chat。
  2. 确认不再弹出图形化登录。
  3. 确认模型显示或使用 gpt-5.5。
  4. 发送测试消息，例如 hello。

正常状态应该是：

  • 不再显示 Reconnecting
  • 不再报 401 Unauthorized
  • 不再报 404 Not Found
  • 请求发往 https://www.souimagery.fun/v1
  • wire_api = "chat" 生效，请求使用 Chat Completions 兼容路径

7. 常见问题

问题 处理方式
添加配置后仍然 Reconnecting 完全关闭并重启 VS Code，确认没有后台残留进程
报 404 Not Found 检查 chatgpt.apiBase 和 openai_base_url 是否都是 https://www.souimagery.fun/v1，并确认带 /v1
报 401 Unauthorized 检查 API key 是否完整正确，auth_mode 是否为 apikey
请求仍发到 api.openai.com 检查 VS Code 是否使用了 chatgpt.apiBase，不要使用无效的 codex.environmentVariables
找不到 codex 命令 执行 npm install -g @openai/codex，然后重新打开终端
VS Code 配置和 CLI 配置不一致 VS Code 看 settings.json 的 chatgpt.*，CLI 看 .codex\config.toml
